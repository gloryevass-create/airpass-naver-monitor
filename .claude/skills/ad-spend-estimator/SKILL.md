# ad-spend-estimator

## 왜 항상 빈 결과인가

원래 계획은 파워링크 노출 도메인을 경쟁사로 매핑(A4)한 뒤 순위·CPC·가정 클릭률·운영일수로
월 예상 광고비를 산출(A5)하는 것이었다. 에어패스 실 계정으로 검증한 결과(사용자 확인 완료,
CLAUDE.md의 "왜 스크래핑을 안 쓰는가" 절 참고):

- 경쟁사가 어떤 도메인으로 파워링크에 노출되는지는 네이버가 제3자에게 공개하는 공식 API가 없다.
- `search.naver.com/robots.txt`가 전체 크롤링을 금지해 스크래핑으로도 얻을 수 없다.

즉 이 데이터를 합법적으로 자동 수집할 방법이 없다. 그래서 이 스킬(`estimateAdSpend`)은
**항상 빈 배열을 반환**하고, `data/raw/<오늘>/ad_spend_estimates.json`에도 빈 배열이 저장된다.

## 이 스킬을 실행하는 이유

파이프라인 흐름(A0~A8)의 일관성을 위해 빈 배열이라도 계속 호출한다. `ad-monitor`는 A7(리포트
작성) 단계에서 이 결과가 비어 있음을 확인하고, **근거 없는 광고비 추정치를 지어내는 대신**
"경쟁사 광고비는 공식 API·합법적 수집 경로가 없어 자동 수집하지 못했다"고 리포트에 명시해야
한다(환각 차단 원칙 — 데이터가 없으면 없다고 쓴다).

```
npx tsx scripts/skills/ad-spend-estimator.ts
```

## 나중에 데이터 소스가 생기면

유료 서드파티 순위추적 서비스 등으로 경쟁사 파워링크 노출 데이터를 확보하게 되면, 이 파일에
노출순위×CPC×가정 클릭률×운영일수 계산식과 `calc_basis` 기록 로직을 다시 채운다(과거 git
히스토리에 초기 구현이 남아 있다).
